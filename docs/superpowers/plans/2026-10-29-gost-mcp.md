# gost-mcp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `gost-mcp`, a stdio MCP server that gives agents exactly three network primitives — an HTTP request through a named egress profile, a path-level connectivity trace, and a temporary public URL for a loopback HTTP service.

**Architecture:** One Go binary in a new module `github.com/go-gost/mcp`, living at `/root/code/go-gost/mcp/`. It imports `github.com/go-gost/x` in-process: `ParseChain` builds a chain without binding, `Chainer.Route(...).Dial` performs egress dials, and the `rtcp` listener plus `tunnel` connector publish a local service through `wisper.gost.run`. No gost daemon and no gost HTTP API are involved.

**Tech Stack:** Go 1.26.3+ (toolchain 1.27.3 available), `github.com/modelcontextprotocol/go-sdk` v1.8.0 (MCP 2026-07-28, stdio), `github.com/go-gost/x` (v0.27.2 or newer), `gopkg.in/yaml.v3`, `golang.org/x/net/dns/dnsmessage`.

**Spec:** `docs/superpowers/specs/2026-10-29-gost-mcp-design.md`

## Global Constraints

- Module path `github.com/go-gost/mcp`; binary name `gost-mcp`; main package at `cmd/gost-mcp`.
- New module lives at `/root/code/go-gost/mcp/`; add `./mcp` to `/root/code/go-gost/go.work`. Do **not** modify `core/`, `x/`, `gost/`, or any other existing module.
- MCP revision 2026-07-28 via go-sdk v1.8.0. Stdio transport only. No HTTP listener.
- stdout is the MCP channel. All diagnostics go to stderr.
- `egress` is required on `gost_run` and `gost_trace`. An unknown name must produce an error that lists the valid names. Never default to direct.
- An empty route must produce `no_route`; never call `Route.Dial` on a route with zero nodes and never fall back to a direct dial.
- Network failures are data: return `ok=false` with a `failure` object and a nil Go error. Protocol errors (`isError=true`) are only for invalid arguments and internal faults.
- No secrets in tool arguments, logs, or the `gost-mcp://egress` resource. `${ENV}` expansion happens at config load.
- Defaults come from the spec: run timeout 30 s / 1 MiB; trace timeout 10 s; wisp TTL 900 s, max TTL 1 h, max leases 4, domain `gost.run`, relay `tunnel+wss://wisper.gost.run:443`.
- Tests: `cd mcp && go test ./...`. Race: `CGO_ENABLED=1 go test -race ./...`. If `go` is missing from PATH, use `/root/.local/go/bin/go`.
- Commit locally after each task with a conventional message. Do not create or push a remote; repository creation on GitHub is the maintainer's call.
- Before any release, verify the module graph with `GOWORK=off go build ./...` (the workspace masks `go.mod`).

## Review Focus

1. **A hop selects no node.** A reasonable person expects the configured chain to be used or an error — never a direct connection. This is gost's `chainRoute.Dial` fallback (`x/chain/route.go:156`). Pinned by `TestRouteRejectsEmptyRoute` (Task 2) and `TestTraceNoRoute` (Task 4).
2. **`egress` missing or misspelled.** A reasonable person expects an error naming the available profiles, never a silent direct request. Pinned by `TestRunRequiresEgress` and `TestRunUnknownEgressListsNames` (Task 5).
3. **Relay re-binds and the public label changes under a live lease.** A reasonable person expects the lease to report the current URL, not keep serving a dead one. Pinned by `TestLeaseURLUpdatesOnRebind` (Task 6).
4. **Response larger than `max_bytes` or binary content.** A reasonable person expects a truncated flag and base64, never an OOM or mojibake. Pinned by `TestRunTruncatesBody` and `TestRunBinaryBodyIsBase64` (Task 3).
5. **The proxy resolves the name and local DNS does not.** A reasonable person expects the request to succeed (split-horizon names); a local `resolve` failure must not abort `gost_run`. Pinned by `TestRunSucceedsWhenLocalResolveFails` (Task 3) and `TestTraceLabelsLocalResolveAsInformational` (Task 4).

- [ ] **Step 3: Implement `failure`**

- [ ] **Step 3: Implement staged tracing**

`Run` computes a deadline from `Timeout` and derives every dial from the remaining budget. Each stage records its own `Stage` and uses `failure.Classify` for the `Code` (so a TLS `EOF` is `{tls, tls_handshake}`, not `internal`). Stages in order:
- `resolve`: `net.DefaultResolver.LookupHost` with a 2 s sub-deadline; always informational; record error but continue.
- `connect`: `e.Route` + `Dial`; on `ErrNoRoute` return immediately with `no_route`.
- `tls`: when the target is TLS (mode `tls`/`https`); record version, ALPN, SNI, cert subject/issuer/not-after.
- `http`: write `HEAD / HTTP/1.1` (or the method implied by the URL) and `http.ReadResponse`; record status and `server` header.
- `read`: for tcp/udp; send `Payload` when present, read up to 4 KiB, apply `Expect`.

Prefix probing: for each cumulative prefix of `e.HopConfigs()` (plus `direct` first), build an `egress.Egress` from a temporary `config.EgressProfile{Name: e.Name, Hops: prefixHops}` and dial the target once with no payload; record `served_by` from `route.Nodes()` names, and stop at the first failure. Then run the full chain through the stage sequence above.

`dns.go`: `resolveVia(ctx, route, resolver, name)` builds an A and an AAAA query with `dnsmessage`, sends over UDP via `route.Dial(ctx,"udp",resolver)`, parses answers; if truncated, retry over TCP. Default resolver comes from the first `nameserver` line in `/etc/resolv.conf`.

When `in.Identity` is set, issue one HTTPS GET to `in.IdentityURL` through the full route and parse `ip`, `country`, `asn`/`asn_org` into `Report.Identity`; a failure here is recorded in `Report.Failure` only if the main diagnosis succeeded, and never masks the main result.
